# CLAUDE.md — project conventions

Financial Intelligence Research Agent: a LangGraph plan-and-execute research agent over SEC
filings and news (Groq LLMs, Weaviate hybrid search, Postgres). **`BUILD_SPEC.md` is the
source of truth**; approved deviations are logged in `docs/DECISIONS.md`.

## Working rules
- **One-time per clone: `uv run pre-commit install`.** The hook (`.pre-commit-config.yaml`)
  runs ruff, ruff format --check and the frontend ESLint on staged files and blocks the
  commit on failure. Don't bypass it (`--no-verify`). mypy + full tests: `make check` / CI.
- Build **phase by phase** (BUILD_SPEC §9). At the end of a phase: lint + typecheck + tests,
  a short summary with how to verify, then stop for approval.
- One branch per phase (`phase-N-<name>`), merged to `main` after approval. Conventional
  commits (`feat:`, `fix:`, `build:`, `docs:`, `test:`, `chore:`).
- **Never fake data, metrics or test results.** If a library/API differs from the spec,
  check current docs, adapt, and add an entry to `docs/DECISIONS.md`.
- No placeholder stubs or dead code in finished phases. Add packages/targets when they get
  real code.

## Hard rules: data safety (owner's rules; they apply in every mode, including auto mode)
The ingested data costs days of Groq/NewsAPI quota to rebuild. An autogenerated migration
once dropped tables (D-038).
- **Back up first** (`.\make.ps1 backup`) before any migration, re-extraction, re-tag or
  bulk delete. Say which backup file was written.
- **Generating and applying a migration are always separate steps.** After
  `alembic revision --autogenerate`, show the owner the migration and wait for their OK
  before `migrate`. Never chain them in one command.
- **Never run destructive commands without asking the owner first:** `DROP`, `TRUNCATE`,
  `DELETE` without `WHERE`, `docker volume rm` / `docker compose down -v`,
  `git reset --hard`, force push, `make restore` into the live database. This includes
  scratch databases and cleanup.
- Backups: `data/backups/<db>-<timestamp>.dump` (pg_dump custom format, gitignored).
  Postgres is the only store to back up. Weaviate is derived from it and is rebuilt
  locally, with no quota, by `uv run python -m ingestion run --only index --force`
  (add `--sample 10` for the sample).

## Layout
- `backend/src/core` — settings, logging, DB engine, Weaviate client (shared by everything)
- `backend/src/api` — FastAPI app (`api.main:app`)
- `backend/src/agent/tools` — the 8 agent tools (Phase 2); `python -m agent.tools list|call|demo`
- `backend/src/agent` — LangGraph graph (Phase 3); `uv run python -m agent ask "..."`
  (also `resume --thread T "answer"`, `history`, `replay`). Prints plan, step modes,
  tokens per node. Live: spends the 120b budget (dev cache makes unchanged reruns free).
- `ingestion/` — EDGAR/NewsAPI pipeline (Phase 1) · `evals/` — eval harness (Phase 6)
- `frontend/` — Next.js 16 App Router, TypeScript, Tailwind v4
- Python is a **uv workspace** (root `pyproject.toml`); one `.venv` at the repo root.

## Commands
Windows PowerShell uses `.\make.ps1 <target>`; Bash/CI uses `make <target>`. Same targets.

| Target | What it does |
|---|---|
| `install` | `uv sync` + `npm ci` in frontend |
| `check` | lint + typecheck + tests + frontend lint/tsc — run before every commit |
| `lint` / `format` / `typecheck` / `test` | ruff / ruff fix / mypy strict / pytest |
| `up` / `down` / `logs` | docker compose stack |
| `ready` | GET `http://localhost:8000/ready` |
| `dev-api` / `dev-web` | run API / frontend on the host with reload |
| `migrate` | apply Alembic migrations (only after the owner approved the migration) |
| `backup` | pg_dump the whole database to `data/backups/` |
| `restore` | `restore <file> [-Database name]` (make: `FILE=… DB=…`); live DB asks for typed confirmation |
| `ingest-sample` | ingest the 10 agreed sample companies |
| `ingest-daily` | resume the full run; stops at the daily token/NewsAPI budgets |
| `ingest-progress` / `ingest-report` | one-line progress / full ingestion report |
| `review-export` / `review-score` | 30-row risk-tag review sheet for the owner / score it |
| `tools-demo` | call every agent tool once against the local stores |

Single test: `uv run pytest backend/tests/unit/test_health.py -k ready`.
Live tests (real Groq/SEC/NewsAPI) are marked `@pytest.mark.live` and excluded by default;
run with `uv run pytest -m live`. Integration tests (`@pytest.mark.integration`) use the local
stack and whatever companies are ingested; they skip themselves when the stack is down.

## Code conventions
- Python 3.12, fully typed, `mypy --strict` clean, ruff (line length 100).
- Short "why" comments at decision points; no comments that restate the code.
- Config only via `core.config.Settings` (pydantic-settings). No secrets or model names in code.
- Logging via stdlib `logging`; JSON output with `run_id`/`thread_id` from ContextVars.
- External calls always have timeouts; tool errors are returned as structured results, never raised into the graph.
- Prompts live in `backend/src/agent/prompts/*.md`, not inline strings.
- Tests: no network. HTTP mocked with `respx`; LLM replaced with a scripted fake.
- Frontend: handle loading/empty/error states; no fake data in the UI.

## Environment gotchas
- `.env` is read from the repo root; `docker-compose` overrides DB/Weaviate hosts for the api container.
- `CORS_ORIGINS` must be a JSON list in `.env`.
- Host ports: compose Postgres **5442**, Weaviate HTTP **8095** / gRPC **50055**. 5432/5433 are native Postgres installs and 8080/8090/50051 belong to another project's Weaviate on the dev machine.
- Windows + async psycopg: use `core.aio.run()` in CLIs and `--loop core.aio:selector_loop` for uvicorn (never bare `asyncio.run`).
- Line endings are LF (`.gitattributes`); `.ps1` files are CRLF.
- Groq quotas are per model: ingestion uses `GROQ_MODEL_*` (gpt-oss-20b); the agent and dev
  testing use `AGENT_MODEL_*` (gpt-oss-120b) via `GroqClient(agent=True)`. Never test against
  the ingestion model while the daily full run is in progress.
